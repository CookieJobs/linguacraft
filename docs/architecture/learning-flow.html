一次 Session = 4 旧 + 6 新

GET /api/learning/session 服务端组装 10 题的逻辑。旧词按 SRS 调度回收, 新词按 CEFR 等级权重 + 词频 + 排除已学来抽。

4 旧词 getDueWords(4)

从 UserWordProgress 找 nextReviewAt ≤ now 的记录, 按时间升序取前 4。越久没复习越先出。 

// learning-scheduler.service.ts:27
userWordProgressModel.find({
  userId, nextReviewAt: { $lte: now }
}).sort({ nextReviewAt: 1 }).limit(limit)
6 新词 vocab.pickWords(6)

从 VocabWord 排除已学过的 lemma, 按 level 对应的 CEFR 权重 + 1/freqRank 打分随机抽。 同 textbook 时优先用 contextualDefinitions。 

// vocab.service.ts:52
score = WEIGHTS[level][cefr] + (1/freqRank) × 0.1
3

Stage → 题型映射

同一单词在不同学习阶段,会被出成不同难度的题。Stage 越深,题越需要主动回忆, 干扰项越接近同 level。

来源 Stage 题型 实现
旧词 0 / 1 choice (四选一) en ↔ zh 随机方向,前端比对 isCorrect
旧词 2 quiz (例句挖空) 用 exampleEn 把 headword 挖空 + 同 level 干扰项
旧词 3 quiz (sentence 降级) ⚠️ sentence 生成器未实装,临时复用 quiz
新词 — choice (四选一) 同 stage 0-1,en ↔ zh 随机

一个新词的生命周期

跟随一个具体的单词走完它从「沉睡在词库」到「长进英语墙」的完整故事。 这一节不用流程图符号,每个节点直接用一段话讲清楚这一阶段到底发生了什么。

1
vocab.schema

沉睡在词库

这个单词安静地躺在 VocabWord 集合里,被打上 headword、lemma、CEFR 等级和所属教材的标签。 它此刻跟任何用户都没有关系,只是一个等待被算法挑中的数据点——一次 seed 启动时, 它从 elementary_vocabulary.json 被批量写进 MongoDB,从此再没动过。

cefr=A1 · levels=[Primary]
2
Stage 0 → 1

首次相遇

用户进入一个学习 session,后端按他选择的 level(比如 Primary)对应的 CEFR 权重表,给这个词打了一个分数, 随机抽中后塞进「6 道新词」里。用户在一道四选一中第一次见到它, 要从干扰项里识别出它的中文释义(或反过来)。答对,后端把 stage 从 0 提到 1,并发一份小奖励。

choice: en ↔ zh · +1 金币 +1 exp
3
Stage 1 → 2

复习闹钟响起

1 天后,后端 scheduler.getDueWords 把它从「到期」队列里捞回来,重新出现在下次 session 的「4 道旧词」里。 题面不再是新的了——但题型没变,还是 choice。这一关是真正的考验:用户是真记住了,还是上轮蒙的? 答对就升 stage 2,进入更长的复习间隔;如果连错 2 次,stage 会退回 0,整个故事要从头来。

+1 day 间隔 · 可回退
4
Stage 2

题型升级

又过 3 天,这个词又回来了,但这次题型变了:不再是 4 选 1,而是用它自己的英文例句挖一个空, 让用户主动写出正确答案。这是关键的跨越——从「我认得它」到「我能想起它」,从识别记忆跨进认知记忆。 例句是系统已经写好的,如果词库里没有真例句,会降级成 choice 题,这条升级路径就不会生效。

quiz: 例句挖空 · +3 day
5
Stage 2 → 3

掌握时刻

这一次,用户答对了。后端把 stage 从 2 升到 3——这是整个生命周期里最重要的一刻: 一条 WordMastery 记录被写入,记下用户造的例句、掌握时间和来源 level; 钱包入账 10 金币,宠物加 10 经验,同时 stats.checkin 记录今日打卡。 从此这个词从「学习中」毕业,正式长进了英语墙,出现在 ReviewPage 的「已掌握」列表里。

+10 金币 · WordMastery · checkin
7 天长复习循环: 掌握后的单词会安静 7 天,直到 nextReviewAt 再次到期。 如果这期间答错,会降回 stage 2 重新进入巩固循环(对应虚线箭头),直到稳定在 stage 3 至少 2-3 轮才算真的「内化」。

上线前 Checklist

距离给真实用户用,产品还有 4 个维度的硬骨头。按依赖关系排序 — 上面没解决的,下面全跑不动。

A 必做 · 阻塞上线

  • ·服务端反作弊 — submitAnswer 必须服务端再判一遍 choice/quiz(对比 wordId + 正确选项 ID),前端 isCorrect 仅作 UX 用。当前实现直接信任前端,有人改本地就能刷金币/掌握数。
  • ·streak 时区 — 选一个权威源(建议后端 UTC),前端彻底从 localStorage 删掉,只展示 getStats().currentStreak。
  • ·rate limit — 至少 /api/learning/session、/api/learning/submit、/api/learning/evaluate 加 IP+userId 限流,DeepSeek 调用尤其防刷。
  • ·邮件配置 — 邮件验证码、找回密码目前是 SMTP 占位,生产必须实配且加 SPF/DKIM,否则进垃圾箱。
  • ·数据脱敏与日志 — 错误日志不打印 email/token/密码,接 Sentry 类工具,生产禁用 console.log。

B 重要 · 可延 1-2 周

  • ·SRS 升级 SM-2 — 写死的 1/1/3/7 天换成 SM-2 公式(EF、interval、repetitions 三参数),按答题质量/反应时调间隔。预期提升 30-50% 长期保持率。
  • ·错题本 — 既然答错已上报,在 UserWordProgress 加 lastWrongAt / wrongTotal 索引,前端做「错题重练」入口(可按学段/教材筛选)。
  • ·sentence 题实装 — Stage 3 真做造句题(用 evaluateSentence 路径),解锁「真掌握」路径,给用户学习曲线一个明显爬升信号。
  • ·词库质量审计 — 跑 scripts/validate-vocab.ts 走一遍,看 isDummyExample 占比、CEFR 分布、缺义词的词条。小学词用户最多,这一档必须先过。
  • ·回归测试 — 后端加 jest e2e(关键:submitAnswer 升 stage/掌握奖励/打卡),前端 jsdom 环境先修一下再跑现有 vitest。

C 法务 · 商业合规

  • ·隐私政策 + 用户协议 — 必须上线前发布,挂在 /privacy、/terms,用户注册时勾选同意。
  • ·未成年人合规 — 主力用户是中小学生,需要 COPPA / 中国《未成年人保护法》双适配:注册年龄≥13(中国实际看情况,建议 12+),家长控制选项,数据可导出/删除。
  • ·词库来源 — 教材是出版社/学校机构内容,如果直接抄人教版/北师大版词表,会有版权风险;建议走正规授权,或者只用基础释义不抄教材。
  • ·DeepSeek 合规 — 用户造句会送 DeepSeek 评估,需在隐私政策里说明,可能要做数据脱敏/去标识。
  • ·支付合规 — 目前金币系统不接支付,如果未来加会员,得接 ICP 备案 + 支付牌照相关要求。

D 运营 · 上线后才有

  • ·监控 — 错误率、API P95、词库命中率、DeepSeek 调用成本/成功率四个仪表盘。
  • ·用户反馈入口 — 学习页右下角小按钮,提交问题带 deviceId + 当前 page,后端收集到表里。
  • ·A/B 框架 — SRS 间隔、题量、新旧词比例都该可调;前端至少用 localStorage 灰度。
  • ·客服话术 + FAQ — 邮箱验证失败、忘记密码、学段改不了 这三类最常见问题提前写好。
  • ·留存机制 — 当前 streak 已经有,但缺 push/邮件提醒。Web Push 浏览器支持不错,先做这个,App 化之后再说。

执行顺序建议

  1. 先把 A.1 反作弊 和 A.2 streak 时区 修了 — 1-2 天能搞定,不改的话上线后数据全是脏的。
  2. 同时让设计/产品补 C.1 隐私政策 和 C.2 未成年人合规 — 这两个是法律红线,改不了技术。
  3. 内部小范围 alpha(50 人) 跑一周,主要看 A.3 rate limit 和 A.4 邮件 在真实环境下有没有漏。
  4. 对外 beta(500-1000 人) 期间,补 B 全部 和 D 全部 — 边运营边迭代。
  5. 正式上线: 开放注册 + 营销活动(教育自媒体 / 家长群)。
